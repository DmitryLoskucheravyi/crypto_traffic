# Crypto Channel Bot

Персональний Telegram-бот на NestJS, який раз на день генерує допис про криптовалюту через OpenAI і публікує його в канал. **Керування — через веб-панель** (логін/пароль), а не через Telegram-команди. Сам Telegram-бот лише публікує в канал і шле push-алерти власнику (нова чернетка / помилка job).

## Стек

NestJS · Express (веб-панель) · nestjs-telegraf (Telegraf) · @nestjs/schedule · Prisma + SQLite · OpenAI SDK.

## Налаштування

1. `npm install`
2. Скопіювати `.env.example` → `.env` і заповнити:
   - `BOT_TOKEN` — токен від @BotFather
   - `CHANNEL_ID` — id каналу (бот має бути адміном з правом публікації)
   - `OWNER_ID` — твій Telegram user id (куди слати алерти)
   - `OPENAI_API_KEY`, за потреби `OPENAI_MODEL`
   - `PROMPT_TEMPLATE` — базовий промпт (редагується тут, без зміни коду)
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD` — логін у веб-панель (обов'язково зміни дефолт!)
   - `SESSION_SECRET` — випадковий рядок 32+ символів для підпису сесійних cookie
3. Застосувати міграції БД:
   ```
   npm run prisma:migrate:dev
   ```
4. Запуск у dev-режимі:
   ```
   npm run start:dev
   ```
5. Відкрити `http://localhost:3000` (або значення `PANEL_PORT`), увійти логіном/паролем з `.env`.

## Веб-панель (повна заміна Telegram-команд)

- Перемикання режиму `off` / `approve` / `auto`.
- Статус: поточний режим, час наступного/останнього запуску.
- "Запустити зараз" — позачерговий запит до GPT, **не** зсуває розклад щоденного тригера. У режимі `off` трактується як `approve` (текст все одно йде на підтвердження в панелі, а не публікується сам).
- Картка чернетки (режим `approve`): "✅ Опублікувати" / "🔁 Перегенерувати" / "❌ Відхилити".
- Історія останніх генерацій/публікацій.

Telegram-бот у приватному чаті з `OWNER_ID` лише сповіщає: "нова чернетка готова, перевір у панелі" та про помилки job — без інтерактивних кнопок.

## Мережевий режим Telegram-бота (не панелі!)

- `BOT_MODE=polling` (за замовчуванням) — бот сам ходить у Telegram за оновленнями, публічний URL не потрібен. Найпростіший варіант.
- `BOT_MODE=webhook` — Telegram сам стукає боту на `WEBHOOK_URL`, слухає на окремому `TELEGRAM_WEBHOOK_PORT` (окремо від веб-панелі):
  - **dev**: піднімаємо тунель (cloudflared/ngrok тощо) на `TELEGRAM_WEBHOOK_PORT`.
  - **прод (Docker)**: той самий підхід — контейнер слухає `TELEGRAM_WEBHOOK_PORT`, назовні проксується через домен/тунель.

Веб-панель завжди працює як звичайний HTTP-сервер на `PANEL_PORT` — її можна тримати за реверс-проксі/тунелем зі своїм доменом незалежно від режиму бота.

## Docker

```
docker compose up --build
```

Використовує той самий `.env`. SQLite-файл монтується через volume `./prisma`, щоб дані не губились між перезапусками контейнера.

## Тести

npm test
