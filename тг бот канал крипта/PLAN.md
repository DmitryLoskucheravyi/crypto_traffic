# План імплементації тг-бота для крипто-каналу

Персональний Telegram-бот, який раз на день за таймером кидає промпт у ChatGPT і генерує допис про криптовалюту в канал. Режими роботи: `off` / `approve` / `auto`. Можливість позачергового запиту (кнопка/команда) без зсуву таймера.

## 1. Стек і інфраструктура
- **Framework**: NestJS (TypeScript)
- **Telegram-інтеграція**: `nestjs-telegraf` (обгортка над Telegraf — `@Update()`, `@Command()`, `@Action()` декоратори)
- **Планувальник**: `@nestjs/schedule` (`@Cron()` для щоденного тригера)
- **Конфіг**: `@nestjs/config` (`.env` — токен бота, OpenAI ключ, `channel_id`, `owner_id`)
- **Персистентність**: Prisma + SQLite (або `better-sqlite3` напряму, якщо без ORM)
- **LLM**: пакет `openai`, обгорнутий у власний `GenerationService`
- **Деплой**: Node.js LTS на VPS через `pm2`, або Docker-контейнер

## 2. Реєстрація бота і каналу
1. Створити бота через @BotFather, отримати токен.
2. Додати бота адміністратором у цільовий канал з правом публікації повідомлень.
3. Зберегти `channel_id` в `.env`.
4. Визначити `owner_id` — тільки власник керує режимами й тисне кнопки.

## 3. Модель даних (мінімальна)
Таблиця/сутність `state`:
- `mode`: `off` | `approve` | `auto`
- `dailyTime`: час щоденного тригера
- `lastRunAt`, `nextRunAt`
- `pendingDraft`: текст чернетки, що чекає апруву (режим `approve`)

## 4. Структура модулів
```
src/
  app.module.ts
  config/                # ConfigModule + валідація .env
  bot/
    bot.module.ts        # nestjs-telegraf.forRoot()
    bot.update.ts        # @Update() — /mode, /status, /post_now, @Action() для кнопок апруву
  scheduler/
    scheduler.module.ts
    scheduler.service.ts # @Cron() job — щоденний тригер
  generation/
    generation.module.ts
    generation.service.ts # виклик OpenAI, формування промпту
  state/
    state.module.ts
    state.service.ts     # режим, pendingDraft, lastRunAt/nextRunAt
  posting/
    posting.module.ts
    posting.service.ts   # публікація в канал через Telegraf
```

## 5. Команди керування ботом
- `/mode off|approve|auto` — перемикання режиму з підтвердженням.
- `/status` — поточний режим, час наступного запуску, останній опублікований пост.
- `/post_now` — позачерговий запит до GPT + генерація допису, **без** зсуву таймера щоденного тригера.
- Inline-кнопки під чернеткою: "✅ Опублікувати", "🔁 Перегенерувати", "❌ Відхилити".

## 6. Логіка генерації допису
1. Базовий промпт-шаблон (тон, довжина, тематика) — редагується в конфізі без зміни коду.
2. `GenerationService.generatePost()` — виклик OpenAI API, повертає текст.
3. Обробка помилок API (retry з backoff, таймаут, ліміти).

## 7. Логіка щоденного тригера (Scheduler)
1. `@Cron()` job спрацьовує о заданій годині.
2. Перевіряє `mode`:
   - `off` → нічого не робить (логування "skip").
   - `approve` → генерує чернетку → зберігає в `pendingDraft` → надсилає власнику з кнопками апруву.
   - `auto` → генерує текст і одразу публікує в канал.
3. Оновлює `lastRunAt` / `nextRunAt`.

## 8. Логіка `/post_now`
1. Викликає ту саму `generatePost()` незалежно від `nextRunAt`.
2. Поведінка залежить від режиму так само, як і в кроці 7 (`approve` → на апрув; `auto` → одразу публікація).
3. **Не** змінює розклад щоденного тригера (`nextRunAt` лишається як був).
4. Вирішити окремо: чи дозволяти ручний пост у режимі `off`.

## 9. Обробка апруву
- "Опублікувати" → публікує `pendingDraft` в канал, очищує чернетку.
- "Перегенерувати" → повторний виклик `generatePost()`, оновлення повідомлення.
- "Відхилити" → чернетка видаляється без публікації.

## 10. Логування і моніторинг
- Логувати кожен запуск (час, режим, результат) у файл/таблицю `history`.
- Команда `/history` — перегляд останніх N постів (опційно).
- Алерт власнику в приватний чат при падінні job з помилкою.

## 11. Тестування
1. Юніт-тест `GenerationService` (мок OpenAI-відповіді).
2. Ручна перевірка кожного режиму на тестовому каналі/групі перед підключенням до бойового каналу.
3. Перевірка, що `/post_now` дійсно не зсуває `nextRunAt`.

## 12. Розгортання
1. `pm2` (auto-restart) або Docker-контейнер з Node-образом.
2. `.env` з токеном бота, OpenAI-ключем, `channel_id`, `owner_id` — не в репозиторії.
3. Healthcheck / алерт при падінні процесу.
