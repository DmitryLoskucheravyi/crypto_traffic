# Crypto Bot (apps/bot)

Персональний Telegram-бот на NestJS, який раз на день генерує допис про криптовалюту через OpenAI і публікує його в канал. **Керування — через єдину адмінку** (`apps/admin`, вкладка "Канал-бот"), а не через Telegram-команди чи власний логін. Цей застосунок сам по собі — лише незалежне admin API (JWT, спільний з `apps/api`) + Telegram-бот, який публікує в канал і шле push-алерти власнику (нова чернетка / помилка job).

## Стек

NestJS · @nestjs/jwt (перевірка спільного admin-токена) · nestjs-telegraf (Telegraf) · @nestjs/schedule · Prisma + SQLite · OpenAI SDK.

## Налаштування

Це частина монорепозиторію `crypto/` — залежності й `.env` спільні на корені, окремо тут нічого не встановлюється.

1. З кореня `crypto/`: `npm install`
2. Корневий `.env` (див. `crypto/.env.example`) має містити:
   - `CHANNEL_BOT_TOKEN` — токен цього бота від @BotFather
   - `CHANNEL_ID` — id каналу (бот має бути адміном з правом публікації)
   - `OWNER_ID` — твій Telegram user id (куди слати алерти)
   - `OPENAI_API_KEY`, за потреби `OPENAI_MODEL`
   - `PROMPT_TEMPLATE` — базовий промпт (редагується тут, без зміни коду)
   - `JWT_SECRET` — спільний з `apps/api`; саме він підтверджує адмін-сесію тут
   - `BOT_PORT` — порт цього admin API (за замовчуванням 3033)
3. Застосувати міграції БД (з кореня):
   ```
   npm run prisma:migrate:dev --workspace apps/bot
   ```
4. Запуск у dev-режимі (з кореня):
   ```
   npm run dev:bot
   ```
5. Керування — в `apps/admin` на вкладці "Канал-бот" (вхід тим самим адмін-логіном, що й для курсів).

## Admin API (викликається з єдиної адмінки)

- `GET /api/status`, `POST /api/mode` — перемикання режиму `off` / `approve` / `auto`.
- `POST /api/post-now` — позачерговий запит до GPT, **не** зсуває розклад щоденного тригера. У режимі `off` трактується як `approve` (текст все одно йде на підтвердження, а не публікується сам).
- `POST /api/draft/publish` / `/regenerate` / `/reject`.
- `GET /api/history` — історія останніх генерацій/публікацій.

Усі ці роути захищені тим самим JWT, що видає `apps/api` при вході в адмінку — окремого логіна тут більше немає.

Telegram-бот у приватному чаті з `OWNER_ID` лише сповіщає: "нова чернетка готова, перевір у панелі" та про помилки job — без інтерактивних кнопок.

## Мережевий режим Telegram-бота (не admin API!)

- `BOT_MODE=polling` (за замовчуванням) — бот сам ходить у Telegram за оновленнями, публічний URL не потрібен. Найпростіший варіант.
- `BOT_MODE=webhook` — Telegram сам стукає боту на `WEBHOOK_URL`, слухає на окремому `BOT_WEBHOOK_PORT` (окремо від admin API):
  - **dev**: піднімаємо тунель (cloudflared/ngrok тощо) на `BOT_WEBHOOK_PORT`.
  - **прод (Docker)**: той самий підхід — контейнер слухає `BOT_WEBHOOK_PORT`, назовні проксується через домен/тунель.

Admin API завжди працює як звичайний HTTP-сервер на `BOT_PORT` — його можна тримати за реверс-проксі/тунелем зі своїм доменом незалежно від режиму бота.

## Docker

Це один із сервісів кореневого `crypto/docker-compose.yml`:

```
docker compose up --build bot
```

Використовує спільний кореневий `.env`. SQLite-файл персиститься через volume `bot-data` (`/app/prisma`), щоб дані не губились між перезапусками контейнера.
