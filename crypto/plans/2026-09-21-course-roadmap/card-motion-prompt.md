# Промпт: появление карточек и анимация объекта при раскрытии (Roadmap)

Дополнение к `implementation-prompt.md` из этой же папки. Контекст проекта и
жёсткие правила — оттуда, раздел 0 (палитра только через токены, никаких новых
библиотек, `prefers-reduced-motion` в каждой анимации, тайминги и кривые только
из `app/lib/motion.ts`).

Затрагиваемые файлы:

- `apps/web/app/components/sections/roadmap.tsx` — появление карточек
- `apps/web/app/components/sections/roadmap-card.tsx` — объект и его анимация
- `apps/api/src/roadmap/*` — новое поле под вторую картинку
- `apps/admin/app/components/roadmap-stage-editor.tsx` — выбор второй картинки

---

## 1. Появление карточек

Сейчас карточка выезжает со сдвигом по X в сторону своего края и по Y вверх,
одним куском, 0.5с. Выглядит плоско: все внутренности появляются монолитом.

Что нужно:

- **Каскад внутри карточки.** Панель проявляется первой, затем с задержкой
  40–60мс идут номер этапа, заголовок, описание, чипы и кнопка. Реализовать
  через `variants` родителя и `staggerChildren`, а не через `delay` на каждом
  элементе вручную.
- **Объект этапа появляется последним** и не вместе с текстом: он должен
  «прилететь» — стартовое состояние `opacity: 0, scale: 0.8, y: -12`, конечное
  `opacity: 1, scale: 1, y: 0`, длительность `DURATION.slow`, задержка ~0.2с от
  начала появления карточки.
- **Направление сдвига оставить привязанным к стороне:** левая колонка выезжает
  из `x: -24`, правая из `x: 24` — это связывает карточку с лентой в центре.
- **Порог срабатывания** оставить `once: true`, `margin: '-80px'`: карточка
  анимируется один раз и не дёргается при обратном скролле.
- Кривая и длительности — только `EASE` и `DURATION` из `lib/motion.ts`.
- При `prefers-reduced-motion` каскада нет: всё сразу в конечном состоянии.

## 2. Анимация объекта при раскрытии «Структура модуля»

Состояние `open` уже живёт в `roadmap-card.tsx`. К нему привязать поведение
картинки в углу карточки:

- **Свёрнуто:** текущее положение, `scale: 1`, лёгкое покачивание при наведении
  на карточку не обязательно.
- **Раскрыто:** объект поднимается на `y: -10`, увеличивается до `scale: 1.18`,
  под ним усиливается свечение (`drop-shadow` акцентом, 0 → 12px), и он слегка
  доворачивается `rotate: -4deg`. Длительность `DURATION.standard`, кривая
  `EASE`.
- Анимировать через `animate={{ ... }}` на `motion.div`-обёртке картинки,
  завязанный на `open` — без отдельного состояния.
- Объект не должен перекрывать текст в раскрытом виде: он висит в правом
  верхнем углу, увеличение идёт «от угла наружу», поэтому
  `transformOrigin: 'top right'`.

## 3. Подмена на фронтальный ракурс

У этапа появляется вторая картинка — тот же объект, развёрнутый передом к
зрителю. При раскрытии карточка показывает её вместо изометрической.

**Данные:**

- `apps/api/src/roadmap/roadmap-stage.schema.ts` — новое поле
  `@Prop({ default: '' }) imageFrontUrl: string;`
- DTO: `imageFrontUrl?: string` с теми же ограничениями, что у `imageUrl`
- Тип `RoadmapStage` в `apps/web/app/lib/api.ts` и в `apps/admin/app/lib/api.ts`
- Админка: второй выпадающий список рядом с первым, варианты
  `/roadmap-1-front.png` … `/roadmap-6-front.png` плюс «без зображення»

**Поведение:**

- Обе картинки лежат в одном контейнере друг над другом, переключение — через
  `opacity` с кроссфейдом `DURATION.standard`, а не через размонтирование:
  подмена не должна моргать пустотой.
- Фронтальная картинка рендерится только если `imageFrontUrl` заполнен. Если
  пусто — работает только подъём и увеличение из пункта 2, без подмены. Это
  обязательное требование: секция должна жить и без второго набора картинок.
- Вторая картинка не должна тянуться по сети до первого раскрытия: у неё
  `loading="lazy"`, и в DOM она добавляется при первом `open`, после чего
  остаётся смонтированной (чтобы повторное раскрытие было мгновенным).
- Обе картинки `aria-hidden`, они декоративные.

## 4. Критерии готовности

- [ ] `npx tsc --noEmit` в `apps/web` и `apps/admin`, `nest build` в `apps/api`.
- [ ] Этап без `imageUrl` — карточка без объекта, раскладка не едет.
- [ ] Этап с `imageUrl`, но без `imageFrontUrl` — подъём и увеличение работают,
      подмены нет, ошибок в консоли нет.
- [ ] Этап с обоими — кроссфейд без моргания и без скачка размера.
- [ ] Повторное раскрытие/сворачивание не перезапускает появление карточки.
- [ ] `prefers-reduced-motion: reduce` — ни каскада, ни подъёма, ни кроссфейда:
      раскрытие просто показывает список тем.
- [ ] Клавиатура: кнопка фокусируется, Enter раскрывает, `aria-expanded`
      меняется, фокус не теряется.
