# CRYPTO SPHEERE

Две вещи и база между ними:

| Что                  | Где        | Чем является                                                    |
| -------------------- | ---------- | --------------------------------------------------------------- |
| Лендинг              | `apps/web` | Статический сайт. Next.js собирает его в `out/`, раздаёт nginx. |
| Бот и приём платежей | `apps/api` | NestJS + Telegraf + слушатель USDT TRC20.                       |
| Заказы               | Mongo      | Только заказы бота. Больше в базе ничего нет.                   |

Админки нет. Контент лендинга лежит в коде и меняется правкой файла + пересборкой.

---

## Лендинг: где лежит контент

Всё, что видно на странице, собрано в двух файлах:

- `apps/web/app/lib/site-data.ts` — данные: уровни курсов, этапы «Пути курса»,
  калькулятор, счётчики, сравнение, бегущая строка, имя бота;
- `apps/web/app/lib/content.ts` — подписи, заголовки, тексты секций, FAQ.

Поменяли — пересобрали — выложили `out/`. Ни одного запроса на сервер страница
не делает: это проверяется тестом `apps/web/test/site-data.test.ts`, который
падает, если в `app/` появится `fetch` или ссылка на удалённую админку.

**Цены на лендинге нет.** Ни на карточках уровней, ни где-либо ещё: стоимость
существует только в боте, поэтому странице нечем с ним разойтись. На карточке —
одна кнопка «Перейти в бот».

Домен для `og:image` задаётся на сборке:

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен npm run build --workspace apps/web
```

## Бот: как продаётся курс

Каталог — `apps/api/src/catalog/catalog.ts`. Три уровня, цены 10 / 25 / 40 USDT.

1. `/start` — бот показывает три уровня с ценами.
2. Выбор уровня — описание, состав, цена, кнопка «Оплатить».
3. «Оплатить» — бот создаёт заказ и называет **точную сумму с хвостом**
   (`10.0304`) и адрес кошелька.
4. Слушатель раз в 20 секунд опрашивает TronGrid по входящим TRC20-переводам.
   Перевод ровно на эту сумму закрывает ровно этот заказ.
5. Материалы уходят в чат автоматически.

### Почему сумма с хвостом

Кошелёк один на всех, поэтому платёж опознаётся не по отправителю, а по сумме.
Каждому ожидающему заказу выдаётся свой хвост в четвёртом знаке — 9999 вариантов
на уровень одновременно. Уникальность держит частичный индекс в Mongo
(`amountKey` среди `pending`), просроченные заказы свою сумму освобождают.

Сравнение сумм идёт в целых через `BigInt`: `10.0304` в double не представима
точно, и округление увело бы платёж к соседнему заказу. Пыль ниже четвёртого
знака отбрасывается — для неё у токена как раз оставлены два лишних знака.

### Что нужно настроить перед запуском

В `.env` (шаблон — `.env.example`):

| Переменная                 | Зачем                                                         |
| -------------------------- | ------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`       | Токен бота.                                                   |
| `TRON_WALLET_ADDRESS`      | Кошелёк для приёма. **Сейчас там заглушка.**                  |
| `TRONGRID_API_KEY`         | Ключ TronGrid. **Сейчас пусто — слушатель выключен.**         |
| `COURSE_MATERIAL_BASIC`    | Чем выдавать курс: путь к файлу, ссылка или telegram file_id. |
| `COURSE_MATERIAL_MEDIUM`   | То же для среднего уровня.                                    |
| `COURSE_MATERIAL_ADVANCED` | То же для продвинутого.                                       |

Без кошелька бот работает, но на «Оплатить» честно отвечает, что приём оплаты не
настроен. Без ключа TronGrid заказы создаются, но не закрываются сами.

Без `COURSE_MATERIAL_*` оплата принимается, а вместо файла уходит сообщение, что
материалы пришлёт менеджер.

## Разработка

```
npm install
npm run dev:all        # mongo в docker + api + web (Windows, PowerShell)
npm run dev:down       # погасить
```

Порознь: `npm run dev:api`, `npm run dev:web`.

Проверки:

```
npm run format:check   # prettier
npm run typecheck      # tsc по обоим проектам
npm test               # jest (api) + vitest (web)
npm run build          # nest build + статический экспорт лендинга
```

### Хуки git

`husky` ставится на `npm install`. Репозиторий на уровень выше проекта, поэтому
`core.hooksPath` указывает на `crypto/.husky`, а сами хуки первым делом заходят
в `crypto/`.

- **pre-commit** — prettier по изменённым файлам (`lint-staged`) + `typecheck`.
- **pre-push** — весь набор тестов.

Дешёвое — на каждый коммит, дорогое — перед отправкой.

### CI/CD

- `.github/workflows/ci.yml` — на каждый пуш и PR: формат, типы, тесты, сборка.
  Готовая статика лендинга уезжает артефактом прогона.
- `.github/workflows/release.yml` — на тег `v*`: образ бота в GHCR и архив
  статики. Секретов сверх `GITHUB_TOKEN` не требует.

## Деплой

```
docker compose up -d --build
```

- `web` — nginx со статикой на `WEB_PORT`;
- `api` — бот и слушатель кошелька на `API_PORT`, ручка `GET /api/health`;
- `mongo` — том `mongo-data`.

Лендинг можно вынести куда угодно отдельно: `apps/web/out` — обычные файлы,
рантайм им не нужен.
